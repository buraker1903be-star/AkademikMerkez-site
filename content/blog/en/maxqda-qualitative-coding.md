## What is qualitative coding?

Coding means attaching **short labels to meaningful segments** of qualitative data such as interview transcripts, focus group recordings or documents. A participant's sentence "I can only work in the evenings once the children are asleep" could, for example, be labelled with the code *time pressure* or *household responsibilities*. The codes are then grouped by similarity and turned into **themes** that answer the research question.

Coding is not a counting exercise; it is an act of **interpretation**. The same data can be coded differently for different research questions, which is why the reasoning behind every decision should be written down.

## Should you code inductively or deductively?

There are two basic approaches, and most studies use both:

- **Inductive (data-driven) coding:** codes emerge from the data as you read. Suitable for exploratory studies and little-known topics.
- **Deductive (theory-driven) coding:** codes are defined in advance from a theory or the literature, and the data are read through that framework.
- **Mixed approach:** you start with main codes drawn from theory and add new sub-codes from the data.

State clearly in your methods section which approach you used and why; it is one of the first things examiners ask.

## Coding in MAXQDA, step by step

1. **Import your data.** Add the interview transcripts (Word, PDF, text) to the Document System. Use pseudonyms or codes in the document names to tell participants apart; do not use real names.
2. **Define document variables.** Enter characteristics such as age group, gender or type of institution as variables. You will need them later to ask "in which group does this theme appear more often?".
3. **First reading and first codes.** Read the text from start to finish, select meaningful segments and create new codes. Do not try to tidy the codes too much in the first round.
4. **Write code definitions.** In each code's memo, write what the code means and when it should and should not be used. These definitions form your codebook.
5. **Keep memos.** As you read, write down interpretations, relationships between codes and doubts in memos. They will later become the raw material for your findings chapter.
6. **Refine the code system.** Merge similar codes, move sub-codes under parent codes and clarify vague codes. Go back to documents you have already coded if necessary.
7. **Build themes.** Ask what each group of codes says about the research question; themes are not the sum of the codes but **patterns of meaning** in the data.

## Why does the codebook matter?

A codebook is a table listing each code's name, definition, inclusion and exclusion criteria, and an example from the data. It serves three purposes:

- It keeps coding **consistent**: it answers "how did I use this code in the first week?" in the third.
- It provides a **shared language** if you work with a second coder.
- Included in the thesis appendix, it shows examiners and reviewers that the analysis is **transparent**.

## How should intercoder agreement be handled?

In some studies, part of the same text is coded independently by two people and agreement is examined. MAXQDA's **Intercoder Agreement** tool compares two coders' coding and lists the segments where they disagree. Disagreements are discussed and code definitions are sharpened; the real gain is this discussion rather than the coefficient itself.

If you report agreement, state which measure you used, which part of the data it was calculated on and how disagreements were resolved.

## How do you report the findings?

Qualitative findings are usually written around **themes**. For each theme:

- Explain in a few sentences what the theme describes.
- Give **direct quotations** that support it, identifying participants by pseudonym (e.g. P7, teacher).
- Discuss how the theme relates to the research question and the literature.

A visual of the code system (MAXQDA's code map or code-document matrix) is useful for showing the structure of the analysis, but it does not replace the findings. Readers should understand the themes from your interpretation and the participants' words, not from a table.
